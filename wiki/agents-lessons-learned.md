# Lessons agents learned the hard way
_Last modified: 2026-11-06_

Past mistakes from building this project, one line each. **Home** is where
the rule is enforced or stated; a lesson with no Home reaches nobody.
Skill `record-a-lesson` adds rows.

| Lesson | Rule | Home |
|---|---|---|
| A test helper's default argument silently kept a test exercising the old behaviour after the code changed. | When a change adds a parameter, grep the test helpers for the default and pass the new case explicitly; break the code and watch the test fail. | `AGENTS.md` (check shown to fail), skill `review` |
| `cmd \| tail` exited 0 while `cmd` failed — hit again as `just preflight 2>&1 \| grep`, whose grep found its pattern in the failing stage's output and printed it as if all was well. | A pipe's status is the last command's: do not pipe a check, or use `set -o pipefail`. Read the output, not the status. | `AGENTS.md` Commands |
| A new test file was invisible to `nix flake check`; hit again when a broken link in a new, untracked wiki page passed `just docs`, which lists files with `git ls-files`. | Flakes and the docs check ignore untracked files: `git add` a new file before `just check` or `just docs`. | `AGENTS.md` Commands, skill `use-a-worktree` |
| `nix flake check --no-build` passed on a check that does its work at build time. | `--no-build` only evaluates the derivation; run the real check (`just check`) without it before claiming the suite passes. | none yet |
| A hand-written `.zcode/config.json` was rewritten by the tool into its own normal form, so `generate --check` reported drift forever. | Generate a tool-managed config in the tool's own normalized form, and test that it round-trips. | skill `new-mapping` (live verification) |
| A denylist of secret-looking keys in discovery logs missed new ones. | Redact by allowlist: keep only named structural values, replace everything else with `{type, length}`. | `docs/SPEC.md` "Privacy", skill `new-mapping` |
| A logger that read the environment leaked variable values into a log. | Reading the environment is opt-in and loud (`--env-be-very-careful`), and logs names only. | `docs/SPEC.md` "Privacy" |
| `src/polymorph.egg-info/` appeared in the working tree after an editable install. | Build output is gitignored (`*.egg-info/`); `just lint` fails if any is tracked. | `.gitignore`, `tests/lint.py` |
| A check that had never failed was trusted. | Every checker ships with a test on a bad input it must flag (`tests/test_docs.py`), and you see it fail before relying on it. | `AGENTS.md`, skill `review` |
| A test that read the ambient environment passed locally and failed on a CI runner: the environment-name test saw `GITHUB_WORKSPACE`. | A test about environment names (or anything the environment can change) runs the CLI with `PATH` only (`run_cli(..., clean=True)` in `tests/test_discover.py`) and adds the variables it needs itself. Run such a test once with extra variables set to see it hold. | `AGENTS.md` Hard rules, skill `new-mapping` (step 5), `tests/test_discover.py` |
| A lint that matched substrings missed what it should catch: `build/` was tracked because the check listed `.egg-info/` only. | Match directory components, not substrings (so `docs/build-notes.md` stays fine), and test each kind of bad input separately, one subtest per kind. | `tests/lint.py`, `tests/test_lint.py` |
| A reported cause was taken as the finding and turned out wrong (three times in one session). | A reported cause is a hypothesis until the code agrees: find the line that produces the symptom and make a test fail for that reason before fixing anything. | skill `investigate-bug` (steps 3-4) |
| A step that goes outward (merge, push, delete) ran before the exit status of the check before it was read. | Read the exit status, not the output you expected, before the first step that goes outward. `just ci-wait` and `just ship-land` exist so that the check and the merge are one refusal, not two things to remember. | skill `ship` (steps 2-3), `AGENTS.md` Hard rules |
| `ship_land.py` merged a PR and then deleted its head branch by name after checking only the base; a fork PR whose head was named `main` would have aimed the delete at the real branch. | A step that deletes by name takes the name from facts read off the PR (`isCrossRepository`, head name and SHA), refuses fork, protected and base-equal heads before merging, and uses `-d` unless the local tip is the verified head. A missing field counts as unsafe. | skill `ship`, `scripts/ship_land.py` and `tests/test_workflow_scripts.py` |
| `capture` killed the harness's process group the moment the harness exited, which also killed the logger children that write late; every test passed because its stub harness logged synchronously. Hit again when the ci-wait stub always returned the complete run list, so `gh run list`'s truncation at its default limit hid a failing run and every test passed. | A stub must be at least as limiting as the thing it stands in for: asynchronous where the real one is asynchronous (a child that writes after the parent exits), truncated where the real one truncates (model the limit so the test can see past it). Settle the log before killing; kill at once only on timeout or signal. | `tests/test_capture.py`, `tests/test_workflow_scripts.py`, `src/polymorph/capture.py` (`run_step`), `scripts/ci_wait.py` |
| A post-landing commit went onto local `experimental` because the checkout was still sitting on it (twice in one session; the push failing on a bad refspec was the only guard). | After every `ship-land`, `git status -sb` before the next commit and branch first — the landing branch is not a workspace. | skill `use-a-worktree` ("check `git status -sb` before anything that changes state"), skill `ship` |
| A redaction guard ran second and never fired: `tool_use_id` sat in the verbatim-allowlist above the id-shape check, so hostile content under that key was logged verbatim and the guard was dead code. | When one branch pre-empts a guard, the guard is dead: test every guard with a value that must FAIL it, not only values that should pass, and put the specific check before the broad allowlist. | skill `review` (checklist), `tests/test_discover.py` RedactionFixTests |
| The loadout-manifest emitter wrote JSON into TOML (`{"k": "v"}`); tomllib rejected it on the second run, so the first run poisoned the second. | Emitting a format with the wrong writer is a round-trip bug: every emitted artifact is parsed back through the real parser by a test, not eyeballed as text. | `tests/test_equip.py` (second-equip round-trip), skill `review` |
| `git commit` failed with "Couldn't get agent socket": the machine's git config asks for SSH-signed commits, and the signing key is a Bitwarden vault item behind the desktop app's agent socket (`~/.bitwarden-ssh-agent.sock`), not a file in `~/.ssh`. | Signing needs `SSH_AUTH_SOCK` pointed at the Bitwarden socket and the vault unlocked. `~/.config/git/ssh-sign` is a `gpg.ssh.program` wrapper that sets the socket before exec'ing ssh-keygen, so non-interactive sessions sign without inheriting the variable; one-off commands can prefix `SSH_AUTH_SOCK=$HOME/.bitwarden-ssh-agent.sock` inline instead. | the wrapper at `~/.config/git/ssh-sign`, wired by the repo-local `gpg.ssh.program` |
| A redaction test's realistic fake tokens (a real-length JWT, a `ghp_…` string) failed the repo's GitGuardian PR check as "Generic High Entropy Secret" and blocked the merge -- twice, because each scan reports only its highest-entropy finding. | Fake secrets use the real token prefix with a flat low-entropy suffix (`ghp_aaaaaaaaaaaa`): still matches credential-detector regexes in code, too dull for secret scanners. | `tests/test_discover.py` (RedactTest) |
| A just recipe's Python heredoc ran as justfile syntax: the body lines were not indented, and `import json` parsed as a valid just import before `dict(os.environ)` finally errored. | In a justfile recipe every heredoc body line carries the recipe's indentation -- just strips it before the interpreter runs, and an under-indented line is parsed as justfile syntax. Isolate recipe-parser breakage in a two-line `/tmp` justfile. | `scripts/run_recipe.py` (refuses a shebang recipe, so recipe logic lives in `scripts/`; `self-check` moved to `scripts/self_check.py`) |
| A validator rejected an explicit `exit = 0` but passed a deny entry with no exit at all; the adapter's `spec.get("exit", 0)` default then rendered every deny as an allow. | When a rule rejects a bad explicit value, reject the field's absence too: the runtime default is often exactly the value you rejected. Write the missing-field case next to the bad-value case. | skill `change-the-schema` (Rules), `tests/test_core.py` (ValidateOutTests) |
| A `$`-anchored `re.match` accepted a version string ending in a newline and logged it verbatim as a safe value. | A whole-string check uses `fullmatch`: `$` also matches before a final newline. | `tests/test_discover.py` (RedactTest), `src/polymorph/discover.py` (`_safe`, `_id_shaped`) |
| Hooks written into `.zcode/config.json` with `enabled: true` never fired: ZCode 3.17.2 held them pending trust, both approval paths dead-ended silently, and the silence looked exactly like a broken mapping. | After wiring hooks in any harness, confirm one actually fires before reading silence as a mapping bug: a harness may refuse to run hooks until they are approved harness-side. | `docs/observed-zcode-session.md` (trust gating), skill `new-mapping` (step 6) |
| The probe hook denied the Edit that added a new probe marker: the matcher matched the marker inside the Edit's payload. | A hook that matches raw payload text fires on payloads quoting its own marker; write placeholders and materialize markers with `sed` built from parts, or expect the installer to self-block. | `docs/observed-zcode-session.md` (hook answers) |
| A zcode guard answering JSON deny failed open: the live session gated calls on exit codes only (JSON deny ran the call, JSON ask drew no prompt, PostToolUse and exit-1 stderr never surfaced). | Probe each answer route in isolation in a live session before claiming it; one hook that both exits 2 and prints JSON lets the exit mask a JSON answer the harness ignores. | skill `new-mapping` step 6, `docs/observed-zcode-session.md` (hook answers) |
| Marker prompts typed into a session that predated the hook wiring produced nothing, while a session started after the wiring fired the same hooks. | Wire the hook config first, start the probing session second: a running session's hook wiring is frozen at its start (zcode 2026-11-04), so config edits land only in new sessions. | skill `new-mapping` (live verification), `docs/observed-zcode-session.md` (the other hook events) |
| Marker grep over the discovery log found nothing, and the first pairing joined on nothing: command and prompt values are `{type, length}` descriptors, `ts` is an epoch float, and `toolCallId` redacted while `tool_use_id` survived. | A discovery log answers shape questions, not content questions: pair on an id the allowlist keeps, parse `ts` as a number, and census the raw file instead of grepping for content. | `docs/discovery.md`, `src/polymorph/discover.py` (`_SAFE_VALUES`, `_CALL_ID_KEYS`) |
| Two wrong "never fires" conclusions from one log: non-tool events hid behind the summary's tool-event filter, and Stop payloads landed only after the session's replies ended. | Before concluding an event never fires, census the raw log with `--event` and read again after the session's replies finish; a filtered aggregate read early is absence-shaped, not evidence. | `docs/cli.md` (`discover summary`), `docs/observed-zcode-session.md` (the other hook events) |
| While one session's round-3 probes ran on a fourteen-hook wiring, a parallel session rewrote the same `.zcode/config.json` underneath it; last writer won on disk and no running session could see the change — both experiments stayed valid only because each session's wiring snapshot predated the other's write. | One writer at a time for workspace hook wiring: sequence wiring experiments across sessions or claim the config, and diff the file before trusting a run's setup — a frozen snapshot can silently diverge from the file. | `docs/observed-zcode-session.md` (wiring freeze), skill `use-a-worktree` |
| The zcode capture driver's entire test coverage ran against stub binaries -- no real zcode session has ever run under polymorph's tooling, and the driver ships blocked anyway. | Stubs prove what the driver writes, not what the harness reads: stub-only coverage is part of a driver's blocked reason, not a step toward removing it; `untested` comes off on live evidence only. | skill `new-mapping` (live verification), `tests/test_capture.py`, `tests/test_probe.py` |
| A markdown link added to AGENTS.md failed `just docs`: the link check reads the basecamp store copy (`git ls-files` skips the root symlink), so the link resolved from `.polymorph/basecamp/`, while GitHub renders the root symlink against the repo root. | Store files reference repo paths as backticked paths, never markdown links: no relative link resolves for both the store copy and the root symlink. | `.polymorph/basecamp/README.md` (store paths), `tests/docs.py` (`check_links`) |
| A scripted word-boundary regex rename edited string literals too: f-string prefixes (`f"..."` became `fetch_proc"..."`), `!r` conversions, the `\n` escape, the `-d` git flag string, and the English article in a doc sentence — five kinds of damage in one pass. | A regex rename edits text, not just identifiers: grep its diff for the new name touching quotes, `!`, backslashes and dashes, and read every changed non-code line before trusting the pass. | `wiki/code-style.md` (Names: scripted renames) |
| A rename gave a comprehension's loop variable the same name its body used for an outer variable, so the body silently compared each entry against itself and the manifest merge dropped every other harness's entries; the merge test caught it. | After renaming a comprehension's loop variable, re-read every other use of that name inside the comprehension — they rebind to the loop variable, not the outer value. A test asserting the merged output (not just the absence of errors) is what sees this. | `tests/test_review_sweep.py` (manifest-merge test), skill `review` |
